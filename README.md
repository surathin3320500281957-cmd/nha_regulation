# ทะเบียนข้อบังคับ คู่มือบริหารชุมชน และหลักเกณฑ์เพิ่มเติม — การเคหะแห่งชาติ

Dashboard เดียวสำหรับค้นหาและสรุป **ขอบเขต / อำนาจ / หน้าที่** ของข้อบังคับ คู่มือปฏิบัติงาน และหลักเกณฑ์/กฎหมายเพิ่มเติมของ กคช. โดยไม่ต้องเปิดอ่าน PDF ทีละไฟล์ — มี 3 tab

**Live URL:** `https://<username>.github.io/<repo-name>/`

---

## 📌 สำหรับ Claude ที่เพิ่งเปิดแชทใหม่

ถ้าผู้ใช้พาคุณมาที่โปรเจกต์นี้ (อัปโหลดไฟล์นี้หรือลิงก์ repo) นี่คือสิ่งที่ต้องรู้ก่อนช่วยงานต่อ:

1. **โครงการนี้มี 3 ชุดข้อมูลคนละธรรมชาติกัน** — อย่าปนกัน:
   - `data.json` = **ข้อบังคับ/ระเบียบ** (กฎเกณฑ์ทั่วไป กำหนดอำนาจ) — 41 รายการ ครบ 100%
   - `manual.json` = **คู่มือปฏิบัติงานหลัก** (ขั้นตอนทำงานจริง) จากไฟล์ "คู่มือสายงานบริหารชุมชน" 612 หน้า — 61 หัวข้อ ครบ 100%
   - `criteria.json` = **หลักเกณฑ์และกฎหมายเพิ่มเติม** (เอกสาร 3 ประเภทผสมกัน — ดูหัวข้อถัดไป) — 14 รายการ ครบ 13 ไฟล์ต้นฉบับ (มี 1 ไฟล์แยกเป็น 2 entry)
2. **`index.html` มี 3 tab** สลับกันโดยใช้ id `viewBrowse` (ข้อบังคับ), `viewManual` (คู่มือหลัก), `viewCriteria` (หลักเกณฑ์เพิ่มเติม) — เขียนด้วย vanilla JS ล้วน ไม่มี framework ไม่มี build step
3. **ทุกอย่างเป็น static site บน GitHub Pages** — ไม่มี backend, ไม่มี database, ไม่มี AI ทำงานอยู่เบื้องหลังหน้าเว็บ (ค้นหาเป็น string matching ล้วนๆ)
4. **ถ้าผู้ใช้ขอให้เพิ่มเอกสารใหม่** → อ่าน PDF ที่เขาอัปโหลด (หรือดึงจาก Google Drive ถ้าเข้าถึงได้) แล้วเพิ่มเป็น object ใหม่ใน `items[]` ของไฟล์ JSON ที่เกี่ยวข้อง ตาม schema ด้านล่าง — **ไม่ต้องแก้ `index.html`** เว้นแต่จะเพิ่มฟีเจอร์ใหม่จริงๆ

## Schema: `manual.json` (คู่มือบริหารชุมชนหลัก 612 หน้า)

```json
{
  "meta": { "title": "...", "source_url": "...", "total_pages": 612, "issued_by": "...", "order_ref": "...", "note": "..." },
  "items": [
    {
      "id": "m_h5_s10",                   // m_h{หมวด}_s{ส่วนที่} หรือ m_appendix_{เลข} สำหรับภาคผนวก
      "chapter_no": 5,                    // 1-7 = หมวดปกติ, 99 = ภาคผนวก
      "chapter_title": "ด้านการจัดการทรัพย์สิน",
      "section_no": "10",
      "title": "การจัดประโยชน์ในชุมชน",
      "page": 214,                        // เลขหน้า "พิมพ์" ในเล่ม (ดูหมายเหตุสูตรแปลงด้านล่าง)
      "sub": ["หัวข้อย่อย 1", "..."],      // fallback เมื่อไม่มี content.steps
      "related_regulation": ["reg_094"],  // เชื่อมไปยัง data.json — คลิกจะสลับ tab อัตโนมัติ
      "note": "หมายเหตุจากตอนทำ index",
      "content": {
        "overview": "ภาพรวมของหัวข้อนี้",
        "steps": [ { "title": "หัวข้อย่อย", "detail": "รายละเอียด/ขั้นตอน" } ],
        "note_extra": "หมายเหตุเพิ่มเติม",
        "data_asof": "บอกว่ายืนยันด้วยภาพจริงแล้วหรือยัง"
      },
      "authority": [                       // มีเฉพาะ ~20/61 หัวข้อ — ป้อนเข้า "ตารางอำนาจอนุมัติรวม" อัตโนมัติ
        { "holder": "ผู้ว่าการ", "category": "อนุมัติสัญญาเช่า", "limit": "ไม่เกิน 200 ล้านบาท", "note": "" }

```

### ⚠️ สำคัญมาก — เรื่องเลขหน้า PDF ของคู่มือหลัก 612 หน้า

**เลขหน้า "พิมพ์" ในเล่ม ≠ เลขหน้า PDF จริง** เพราะมีหน้าปก/สารบัญคั่นอยู่ก่อน — สูตรแปลงที่ยืนยันแล้ว (คงที่ตลอดทั้งเล่ม):

```
PDF_page = printed_page + 11
```

ตัวอย่าง: field `page: 354` (หน้าพิมพ์) → ต้องใช้ `pdftoppm -f 365 -l 375` (PDF จริง) ถึงจะได้หน้าที่ถูกต้อง — **เคยพลาดจุดนี้มาแล้วครั้งหนึ่ง** ถ้าจะกลับไปอ่านหน้าเพิ่มเติมในคู่มือหลัก ต้องบวก 11 เสมอ (สูตรนี้ใช้เฉพาะไฟล์ manual.json ต้นทาง ไม่เกี่ยวกับไฟล์ใน criteria.json ซึ่งแต่ละไฟล์อ่านตรงได้เลยไม่ต้องแปลงเลขหน้า)

## Schema: `criteria.json` (หลักเกณฑ์และกฎหมายเพิ่มเติม) ⭐ ใหม่ล่าสุด

ชุดข้อมูลนี้**ต่างจาก 2 ชุดข้างบนโดยพื้นฐาน** — มาจากโฟลเดอร์ Google Drive แยกต่างหากชื่อ **"หลักเกณฑ์และกฏหมายเพิ่มเติม"** และ**จะมีเอกสารใหม่เพิ่มเข้ามาเรื่อยๆ** (หน่วยงานทำบันทึกอ้างอิงกฎหมายภายนอก + คู่มือเฉพาะเรื่อง + บันทึกอนุมัติกรณีเฉพาะ)

```json
{
  "meta": { "title": "หลักเกณฑ์และกฎหมายเพิ่มเติม", "source_folder": "...", "checked_as_of": "...", "total_records": 14 },
  "items": [
    {
      "id": "crit_xxx",
      "doc_type": "case_memo",              // "external_law" | "specialized_manual" | "case_memo" — 3 ประเภทเท่านั้น
      "title": "ชื่อเรื่องเต็ม",
      "date": "...",
      "source_url": "https://drive.google.com/file/d/.../view",

      "case_ref": "โฉนดที่ดินเลขที่ 51299",       // เฉพาะ case_memo — อ้างอิงกรณี/โครงการเฉพาะ (null ถ้าไม่มี)
      "applies_to": "กรณีที่ดินว่างติดศูนย์ชุมชน", // ใช้เทียบเคียงกรณีคล้ายกันได้ไหม

      "authority_basis": {                    // ⭐ หัวใจของ schema นี้ — ตอบ 3 คำถามเสมอ: ใคร/หลักอะไร/มติไหน
        "decision_maker": "ผู้ว่าการ",          // ใครมีอำนาจ (ชื่อตำแหน่ง ไม่ใช่ชื่อคน)
        "legal_grounds": [                      // อาศัยหลักอะไร — มีได้หลายข้อ หรือ [] ถ้าไม่มี
          { "type": "regulation", "ref": "ข้อบังคับฉบับที่ 94", "link_id": "reg_094" }  // link_id เชื่อมข้าม tab ได้ถ้ามีอยู่ในทะเบียนแล้ว
        ],
        "resolution_ref": "มติคณะกรรมการ กคช. ครั้งที่ 5/2568 ...",  // จากมติ/บันทึกไหน (null ถ้าไม่มี)
        "confidence": "confirmed"    // "confirmed" (อ่านครบยืนยันแล้ว) | "partial" (อ่านได้บางส่วน) | "pending" (ยังไม่ได้อ่าน)
      },

      "content": {
        "overview": "ภาพรวม",
        "steps": [ { "title": "...", "detail": "..." } ]
      },
      "authority": [ ... ],   // optional — ใช้ schema เดียวกับ manual.json ถ้าเอกสารมีตารางอำนาจแบบมีโครงสร้าง (ป้อนเข้าตารางรวมเดียวกัน)
      "tags": ["คำสำคัญ"],
      "related_regulation": ["reg_094"]   // เชื่อมกลับ data.json
    }
  ]
}
```

### แนวทางจัดประเภท `doc_type` (สำคัญเวลาเพิ่มไฟล์ใหม่)

| doc_type | ลักษณะ | ตัวอย่าง |
|---|---|---|
| `external_law` | กฎหมาย/ข้อบัญญัติจากหน่วยงานภายนอก ไม่ใช่ กคช. ออกเอง | พ.ร.บ.การเคหะแห่งชาติ, ข้อบัญญัติ กทม., กฎกระทรวง |
| `specialized_manual` | คู่มือปฏิบัติงานเฉพาะเรื่อง แยกเล่มจากคู่มือหลัก 612 หน้า | คู่มือนิติบุคคลอาคารชุด, คู่มือจัดซื้อจัดจ้าง |
| `case_memo` | บันทึกอนุมัติ/ตัดสินใจเฉพาะกรณี ไม่ใช่กฎทั่วไป แต่เป็นบรรทัดฐาน (เหมือน "คำพิพากษา" มากกว่า "กฎหมาย") | บันทึกอนุมัติยกเลิกสัญญา, บันทึกทบทวนหลักเกณฑ์ซ่อมอาคาร |

**หมายเหตุจากประสบการณ์อ่านจริง:** เอกสารของ กคช. หลายฉบับเป็น **"แฟ้มคดี" ซ้อนหลายปี** ในไฟล์เดียว (บันทึกเดิม + บันทึกทบทวน + รายงานการประชุม) — อ่านให้ครบทั้ง chain ก่อนสรุป `authority_basis` และบางไฟล์มีเอกสาร 2 ประเภทซ้อนกัน (เช่น บันทึกสั้นๆ + กฎหมายแม่บทฉบับเต็มแนบท้าย) ให้แยกเป็น 2 entry คนละ `doc_type` ตามที่เกิดขึ้นจริงกับไฟล์ "การจัดตั้งนิติบุคคลชุมชน กคช." ที่แยกเป็น `crit_juristic_person_training` (case_memo) กับ `crit_nha_act_1994` (external_law คือ พ.ร.บ.การเคหะแห่งชาติ พ.ศ.2537 ฉบับเต็ม)

## สถานะปัจจุบัน (ล่าสุด)

| ชุดข้อมูล | ความสมบูรณ์ |
|---|---|
| `data.json` — ข้อบังคับ/ระเบียบ | **41/41 ฉบับ (100%)** สรุปละเอียดครบ พร้อมตารางอำนาจ |
| `manual.json` — เนื้อหาคู่มือหลัก (`content`) | **61/61 หัวข้อ (100%)** ยืนยันด้วยภาพต้นฉบับจริงทุกหัวข้อ |
| `manual.json` — ตารางอำนาจแบบมีโครงสร้าง (`authority[]`) | **20/61 หัวข้อ** — ยังไม่ครบ ทำเพิ่มได้เรื่อยๆ |
| `criteria.json` — หลักเกณฑ์เพิ่มเติม | **14/14 รายการ (ครบทั้ง 13 ไฟล์ต้นฉบับ)** — 8 case_memo, 3 external_law, 3 specialized_manual |

### งานที่ค้าง/ต่อยอดได้ในอนาคต (ถ้าผู้ใช้ถามถึง)

1. **ระเบียบใหม่ที่พบซ่อนอยู่ในคู่มือ แต่ยังไม่อยู่ใน `data.json`** (พบระหว่างอ่านคู่มือหลัก 612 หน้า):
   - ระเบียบว่าด้วยการให้เช่า ให้เช่าซื้อ หรือซื้อ อาคาร ที่ดินฯ พ.ศ.2543 (+ฉบับที่ 2 พ.ศ.2562) — ภาคผนวก 13-14 ของ manual.json
   - ระเบียบว่าด้วยการให้เช่าโครงการเคหะชุมชนดินแดงฯ พ.ศ.2563 (+ฉบับที่ 2) — ภาคผนวก 15-16
   - ระเบียบว่าด้วยการจัดประโยชน์ทรัพย์สิน 4 ฉบับย่อย พ.ศ.2563 — หมวด 5 ส่วนที่ 10.2-10.5
   - ระเบียบการจัดเก็บเงินและการนำส่งเงิน ฉบับที่ 2 พ.ศ.2563 — ภาคผนวก 17-18
2. **คำสั่งมอบอำนาจปี 2565 (manual.json ภาคผนวก 7-12) อาจล้าสมัย** — คู่มือหลัก (ปรับปรุงปี 2566) ยังอ้างอิงคำสั่งชุดปี 2565 แต่ข้อบังคับหลัก `reg_delegation` ในทะเบียนเป็นฉบับปี **2568** (ออกทีหลัง 2 ปี) — ควรตรวจสอบว่าคำสั่งปี 2565 ยังมีผลบังคับใช้คู่ขนานหรือถูกยกเลิกไปแล้ว
3. **`manual.json` authority[] ยังไม่ครบทุกหัวข้อ** ที่มีข้อมูลอำนาจ — ทำเพิ่มได้เรื่อยๆ ตาม schema ด้านบน แล้วตาราง "⚖️ ตารางอำนาจอนุมัติรวม" จะอัปเดตอัตโนมัติ
4. **`criteria.json` จะมีเอกสารใหม่เข้ามาเรื่อยๆ** — เมื่อผู้ใช้ส่งไฟล์ใหม่จากโฟลเดอร์ "หลักเกณฑ์และกฏหมายเพิ่มเติม" ให้เพิ่มเป็น item ใหม่ตาม schema ข้างบน จัดประเภท `doc_type` ให้ถูกต้อง และพยายามสกัด `authority_basis` ให้ครบ 3 คำถาม (ใคร/หลักอะไร/มติไหน) ทุกครั้ง แม้จะรู้ไม่ครบก็ให้ใส่เท่าที่รู้พร้อม `confidence: "partial"`
5. **คู่มือปฏิบัติงานด้านการบริหารนิติบุคคลอาคารชุด** ใน criteria.json สรุปจากเนื้อหาที่มี (~135,000 ตัวอักษร) ครบทุกส่วนหลัก แต่ยังมีภาคผนวก (ตัวอย่างเอกสาร, ประเด็นปัญหา/แนวทางแก้ไข, การบริหาร Pack 1) ที่ยังไม่ได้สรุปละเอียดทุกหน้า — เจาะลึกเพิ่มได้ถ้าต้องการ
6. **คู่มือการจัดซื้อจัดจ้างฯ ใน criteria.json** — ไฟล์ที่มีอยู่เป็นแค่บันทึกแจ้งเวียน/ปกแจกจ่าย ไม่ใช่เนื้อหาคู่มือฉบับเต็ม (`confidence: "partial"`) — ถ้าต้องการเนื้อหาเต็มต้องขอไฟล์จริงจากฝ่ายพัสดุ (พค.) เพิ่มเติม

- คลิกปุ่มเชื่อมโยง (🔗) ในหัวข้อคู่มือ/หลักเกณฑ์ → สลับ tab ไปเปิดฉบับข้อบังคับที่เกี่ยวข้องให้อัตโนมัติ

## เทคนิคที่ใช้ตอนอ่าน PDF สแกน/ภาพ (ถ้าต้องอ่านเพิ่มในอนาคต)

หลายไฟล์เป็น PDF สแกนหรือมีเนื้อหาฝังเป็นรูปภาพในไฟล์ Word ที่แปลงเป็น PDF (`pdftotext` อ่านไม่ออกแม้จะเป็นไฟล์ digital) — วิธีที่ได้ผล:

```bash
pdftoppm -jpeg -r 150 -f <หน้าเริ่ม> -l <หน้าจบ> input.pdf output_prefix
tesseract output_prefix-XXX.jpg - -l tha
```

**บทเรียนสำคัญ:**
- อย่าเชื่อว่า `pdftotext` คืนค่าว่างแปลว่า "ไม่มีเนื้อหา" — ลอง OCR ด้วย tesseract ก่อนสรุปว่าหน้านั้นไม่มีข้อความเสมอ
- ก่อนอ่าน PDF ด้วย `pdftoppm` ให้ลอง `Google Drive:read_file_content` ก่อนเสมอ (เร็วกว่ามาก ไม่ต้องดาวน์โหลด/แปลงภาพ) — ใช้ได้ดีกับไฟล์ digital-native แม้ไฟล์จะมีขนาดใหญ่มาก (เจอไฟล์ 48MB ที่จริงมีแค่ ~135,000 ตัวอักษร อ่านได้ในเรียกครั้งเดียว เพราะขนาดไฟล์ใหญ่จากรูปภาพความละเอียดสูง ไม่ใช่จากปริมาณข้อความ) — ใช้ `pdftoppm`+OCR เฉพาะเมื่อ `read_file_content` คืนค่าว่างหรือแค่ placeholder หน้า
