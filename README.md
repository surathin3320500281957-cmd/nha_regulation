# ทะเบียนข้อบังคับและระเบียบ การเคหะแห่งชาติ

เว็บแอปหน้าเดียว (Single-file, ไม่ต้อง build) สำหรับค้นหา/สรุปขอบเขต อำนาจ และหน้าที่ ของระเบียบ ข้อบังคับ คู่มือ และหลักเกณฑ์ต่างๆ แทนการเปิดอ่าน PDF ทีละไฟล์

เว็บนี้รันบน **GitHub Pages** ที่: `https://surathin3320500281957-cmd.github.io`

---

## 1. โครงสร้างไฟล์ทั้งหมด

```
├── index.html          ← หน้าเว็บทั้งหมด (HTML + CSS + JavaScript อยู่ในไฟล์เดียว)
├── data.json            ← ข้อมูลแท็บ "ระเบียบและข้อบังคับ"
├── manual.json           ← ข้อมูลแท็บ "คู่มือบริหารชุมชน"
├── procurement.json      ← ข้อมูลแท็บ "คู่มือจัดซื้อจัดจ้าง"
└── criteria.json          ← ข้อมูลแท็บ "หลักเกณฑ์เพิ่มเติม"
```

**หลักการสำคัญ:** `index.html` ไม่มีข้อมูลฝังอยู่ในตัวเองเลย มันแค่ดึง (`fetch`) ไฟล์ `.json` ทั้ง 4 ตัวนี้มาแสดงผลตอนโหลดหน้า/สลับแท็บ ดังนั้น **การเพิ่ม-แก้-ลบข้อมูล ทำได้โดยแก้ไฟล์ `.json` เพียงอย่างเดียว ไม่ต้องแตะ `index.html` เลย** (ยกเว้นกรณีอยากเพิ่มแท็บใหม่ทั้งแท็บ)

ทั้ง 4 ไฟล์ต้องอยู่ **โฟลเดอร์เดียวกับ `index.html`** เสมอ ไม่งั้นจะขึ้น error "โหลด xxx.json ไม่สำเร็จ"

---

## 2. แผนที่ 4 แท็บ

| แท็บ | ไฟล์ข้อมูล | โครงสร้างข้อมูล | ใช้สำหรับ |
|---|---|---|---|
| 📋 ระเบียบและข้อบังคับ | `data.json` | รายการเดี่ยว (แต่ละฉบับ = 1 item พร้อมเนื้อหาเต็ม) | ระเบียบ/ข้อบังคับที่ กคช. ออกเองอย่างเป็นทางการ |
| 📘 คู่มือบริหารชุมชน | `manual.json` | แบนราบ (แต่ละหัวข้อย่อย = 1 item, มี `chapter_title` ไว้กรอง) | คู่มือเล่มใหญ่ที่แบ่งเป็นหมวด/ส่วน |
| 📦 คู่มือจัดซื้อจัดจ้าง | `procurement.json` | แบนราบ เหมือน manual.json | คู่มือเฉพาะเรื่องจัดซื้อจัดจ้างฯ (แยกออกมาเพราะใช้บ่อย) |
| 📚 หลักเกณฑ์เพิ่มเติม | `criteria.json` | รายการเดี่ยว (คละประเภท) | บันทึกกรณีเฉพาะ, กฎหมายอ้างอิงภายนอก, คู่มือเฉพาะเรื่องอื่นๆ ที่ยังไม่มีแท็บของตัวเอง |

**เหตุผลที่คู่มือจัดซื้อจัดจ้างมีแท็บแยก แต่คู่มืออื่นยังอยู่ใน "หลักเกณฑ์เพิ่มเติม":** เพราะจัดซื้อจัดจ้างใช้งานบ่อยมาก การฝังอยู่ใน "หลักเกณฑ์เพิ่มเติม" ต้องกด 3 ชั้น (แท็บ → กรองประเภท → คลิกการ์ด) จึงแยกเป็นแท็บหลักให้เข้าถึงใน 1 คลิก ส่วนคู่มือ/หลักเกณฑ์อื่นที่ใช้ไม่บ่อยเท่ายังคงไว้แบบเดิมได้

## 3. วิธีอัปเดตข้อมูลในแต่ละแท็บ (งานที่จะเจอบ่อยที่สุด)

### 3.1 เพิ่ม/แก้ "ระเบียบและข้อบังคับ" (`data.json`)

โครงสร้างแต่ละรายการ:

```json
{
  "id": "reg_xxx_unique",
  "chabap": "12",
  "title": "ชื่อระเบียบ/ข้อบังคับเต็ม",
  "date": "1 มกราคม 2566",
  "amendments": "ฉบับที่ 2 (2567)",
  "category": ["ที่ดิน/ทรัพย์สิน"],
  "source_url": "https://drive.google.com/file/d/xxx/view",
  "hasDetail": true,
  "tags": ["คำค้น1", "คำค้น2"],
  "related": ["reg_อีกฉบับที่เกี่ยวข้อง"],
  "summary": {
    "scope": "ข้อความอธิบายขอบเขตของระเบียบนี้",
    "authority": [
      { "holder": "ผู้ว่าการ", "limit": "ไม่เกิน 50 ล้านบาท", "note": "หมายเหตุ (ถ้ามี)" }
    ],
    "committees": [
      { "name": "คณะกรรมการ...", "composition": "องค์ประกอบ", "duties": ["หน้าที่ 1", "หน้าที่ 2"] }
    ],
    "methods": "ข้อความอธิบายวิธีดำเนินการ"
  },
  "sections": [
    { "no": "ข้อ 5", "text": "เนื้อหาเต็มของข้อนี้" }
  ]
}
```

**field ที่จำเป็นต้องมี:** `id`, `title`, `date`, `category`, `hasDetail`
**field ที่ใส่เมื่อมีข้อมูลพร้อม:** `summary`, `sections`, `tags`, `related` — ถ้ายังไม่มี ให้ตั้ง `"hasDetail": false` และไม่ต้องใส่ `summary`/`sections` เว็บจะแสดงข้อความ "ยังไม่ได้สรุป" ให้อัตโนมัติ

> **category ที่มีสีกำหนดไว้แล้ว:** ที่ดิน/ทรัพย์สิน (เขียว), บุคคล/พนักงาน (ส้ม), การเงิน/บริหารทั่วไป (ม่วง), ธรรมาภิบาล/บริหาร (แดง) — ถ้าตั้งชื่อหมวดใหม่นอกเหนือจากนี้ ระบบจะให้สีม่วงเป็นค่าเริ่มต้น ไม่ error แต่ถ้าอยากได้สีเฉพาะ ต้องเพิ่มใน `CAT_COLORS` ใน `index.html`

### 3.2 เพิ่ม/แก้หัวข้อใน "คู่มือบริหารชุมชน" (`manual.json`) หรือ "คู่มือจัดซื้อจัดจ้าง" (`procurement.json`)

ทั้งสองไฟล์ใช้โครงสร้างเดียวกัน (แบนราบ ไม่ซ้อนชั้น):

```json
{
  "meta": {
    "total_pages": 612,
    "source_url": "https://drive.google.com/file/d/xxx/view"
  },
  "items": [
    {
      "id": "pm_2_4",
      "chapter_no": 2,
      "chapter_title": "วิธีจัดซื้อจัดจ้างและเกณฑ์วงเงิน",
      "section_no": 4,
      "title": "อำนาจอนุมัติงบประมาณจัดซื้อจัดจ้าง",
      "page": 25,
      "content": {
        "overview": "ข้อความภาพรวม",
        "table": {
          "title": "ชื่อตาราง (ใส่หรือไม่ก็ได้)",
          "columns": ["คอลัมน์ 1", "คอลัมน์ 2"],
          "rows": [
            ["ค่า 1", "ค่า 2"],
            ["ค่า 1", "ค่า 2"]
          ],
          "footnote": "หมายเหตุใต้ตาราง (ใส่หรือไม่ก็ได้)"
        },
        "steps": [
          { "title": "ขั้นตอน 1", "detail": "รายละเอียด" }
        ],
        "note_extra": "หมายเหตุเพิ่มเติม"
      }
    }
  ]
}
```

**field ที่จำเป็นต้องมี:** `id` (ห้ามซ้ำกับ item อื่นในไฟล์เดียวกัน), `chapter_no`, `chapter_title`, `section_no`, `title`
**field ใน `content` ทั้งหมดใส่หรือไม่ใส่ก็ได้** เว็บจะแสดงเฉพาะส่วนที่มีข้อมูล — เพิ่มเมื่อมีข้อมูลจริง:
- `overview` → ข้อความภาพรวม
- `table` → ตารางเดียว
- `steps` → รายการขั้นตอน (แต่ละอันมี title+detail)
- `note_extra` → กล่องหมายเหตุสีน้ำเงิน

> **หมายเหตุเรื่องเลขหน้า (`page`):** ถ้าไม่มีต้นฉบับที่ระบุเลขหน้าไว้ชัดเจน (เช่นเปิดจาก Google Drive แล้วไม่มีเลขหน้ากำกับ) ให้ข้าม field นี้ไปได้เลย เว็บจะไม่แสดงเลขหน้าให้ ไม่ error แต่จะใช้ "บทที่ X · ส่วนที่ Y" อ้างอิงแทน

**ปุ่ม "ตารางสรุปวงเงิน/อำนาจอนุมัติ"** (ปุ่มม่วงมุมขวาบนของแต่ละแท็บ) ดึงจาก `meta.summary_view` ซึ่งเป็น field เสริม ไม่บังคับต้องมี:

```json
"meta": {
  "total_pages": 612,
  "source_url": "...",
  "summary_view": {
    "title": "📊 สรุปวงเงิน / วิธีจัดซื้อ / อำนาจอนุมัติ / ระยะเวลา",
    "tables": [
      {
        "title": "ชื่อตารางที่ 1",
        "columns": ["คอลัมน์ 1", "คอลัมน์ 2"],
        "rows": [["ค่า", "ค่า"]],
        "footnote": "หมายเหตุ (ถ้ามี)"
      }
    ]
  }
}
```
ถ้าไม่ใส่ `summary_view` ปุ่มจะกดได้แต่ขึ้นข้อความ "ยังไม่มีข้อมูลตารางสรุป" แทน — ไม่ error

### 3.3 เพิ่ม/แก้ "หลักเกณฑ์เพิ่มเติม" (`criteria.json`)

```json
{
  "meta": { },
  "items": [
    {
      "id": "crit_xxx_unique",
      "doc_type": "case_memo",
      "title": "ชื่อเรื่อง",
      "date": "1 มกราคม 2567",
      "case_ref": "บันทึกที่ พม xxxx/xxxx",
      "applies_to": "ใช้เทียบเคียงได้กับกรณีที่คล้ายกัน เช่น ...",
      "source_url": "https://drive.google.com/file/d/xxx/view",
      "tags": ["คำค้น1"],
      "related_regulation": ["reg_id_ที่เกี่ยวข้องในแท็บระเบียบ"],
      "authority_basis": {
        "decision_maker": "ผู้ว่าการ",
        "legal_grounds": [
          { "ref": "พ.ร.บ. xxx พ.ศ. xxxx", "type": "law" }
        ],
        "resolution_ref": "บันทึกที่ xxx ลว. xx/xx/xxxx",
        "confidence": "confirmed"
      },
      "content": {
        "overview": "ภาพรวมเรื่องนี้",
        "steps": [
          { "title": "ขั้นตอน 1", "detail": "รายละเอียด" }
        ]
      }
    }
  ]
}
```

**`doc_type` มี 3 ค่าที่ระบบรู้จัก** (กำหนดสี badge และตัวกรองอัตโนมัติ):
| ค่า | แสดงเป็น |
|---|---|
| `case_memo` | บันทึกกรณีเฉพาะ (สีส้ม) |
| `external_law` | กฎหมายอ้างอิงภายนอก (สีแดง) |
| `specialized_manual` | คู่มือเฉพาะเรื่อง (สีฟ้า) |

ถ้าตั้ง `doc_type` เป็นค่าอื่นนอกเหนือจากนี้ เว็บไม่ error แต่จะไม่มีสี/ป้ายกำกับที่สวยงาม (ควรเพิ่มใน `DOCTYPE_LABEL` ใน `index.html` ถ้าจะมีประเภทใหม่ถาวร)

**`authority_basis.confidence` มี 3 ค่า** ใช้กับสถิติ 4 ช่องด้านบน (เอกสารทั้งหมด/ยืนยันแล้ว/ทราบบางส่วน/ยังไม่ได้อ่าน):
- `confirmed` → ✓ ยืนยันแล้ว (เขียว)
- `partial` → ◐ ทราบบางส่วน (ส้ม)
- `pending` หรือไม่ใส่ field `authority_basis` เลย → ○ ยังไม่ได้อ่าน (เทา)

**field ที่จำเป็นต้องมี:** `id`, `doc_type`, `title`
**field อื่นทั้งหมดใส่หรือไม่ใส่ก็ได้** ตามข้อมูลที่มีจริง

> ⚠️ **สิ่งที่ไม่ควรทำแล้ว:** เดิม `criteria.json` เคยรองรับ item แบบ "คู่มือเชิงลึก" ที่มี field `is_deep_manual: true` และ `chapters: [...]` ซ้อนกันหลายชั้น (ใช้กับคู่มือจัดซื้อจัดจ้างตอนที่ยังไม่แยกแท็บ) ตอนนี้ **เลิกใช้รูปแบบนี้แล้ว** — ถ้ามีคู่มือเล่มใหม่ที่อยากให้มีบท/หัวข้อละเอียดแบบนี้ ให้ทำตามข้อ 4 (สร้างแท็บใหม่ + ไฟล์ json แบบแบนราบ) แทน จะดูแลง่ายกว่ามาก

## 4. เพิ่มคู่มือเล่มใหม่เป็นแท็บของตัวเอง (งานใหญ่ ทำเป็นครั้งคราว)

ถ้ามีคู่มือเล่มใหม่ที่คาดว่าจะใช้บ่อย (เหมือนกรณีคู่มือจัดซื้อจัดจ้าง) และอยากให้มีแท็บของตัวเองแทนที่จะฝังใน "หลักเกณฑ์เพิ่มเติม" ให้ทำตามนี้:

1. **เตรียมข้อมูล** — ส่งเนื้อหาคู่มือ (PDF หรือสรุปเป็นบท/หัวข้อ) มาให้ช่วยแปลงเป็นไฟล์ `.json` แบบแบนราบ (โครงสร้างเหมือนข้อ 3.2)
2. **สร้างไฟล์ใหม่** เช่น `xxxmanual.json`
3. **แก้ `index.html` 3 จุด:**
   - เพิ่มปุ่มแท็บใหม่ใน `<div class="tab-bar">`
   - เพิ่ม `<div class="view" id="viewXxx">...</div>` (คัดลอกโครงจากแท็บ "คู่มือจัดซื้อจัดจ้าง" ได้เลย เพราะโครงสร้างเหมือนกัน)
   - เพิ่มชุดฟังก์ชัน JS (`loadXxx`, `renderXxxStats`, `renderXxxChips`, `renderXxxList`, `renderXxxDetail` ฯลฯ) โดยคัดลอกจากชุดฟังก์ชันของแท็บคู่มือจัดซื้อจัดจ้างแล้วเปลี่ยนชื่อตัวแปร/id

**ทางลัด:** ไม่ต้องทำเองก็ได้ — ส่งเนื้อหาคู่มือมาบอกได้เลยว่า "อยากได้แท็บใหม่ชื่อ ... " แล้วจะจัดการให้ครบทั้งไฟล์ json และแก้ index.html ให้

## 5. คำเตือน/ข้อควรระวังเวลาแก้ไฟล์ JSON เอง

1. **`id` ต้องไม่ซ้ำกัน** ภายในไฟล์เดียวกัน (ถ้าซ้ำ การ์ดจะเลือกผิดรายการ)
2. **ทุกไฟล์ต้องเป็น JSON ที่ถูกต้อง (valid)** — เครื่องหมายจุลภาค `,` ท้ายรายการสุดท้ายในลิสต์ต้อง**ไม่มี**, ทุกคีย์/ข้อความต้องอยู่ใน `"..."` เท่านั้น แนะนำเช็คด้วยเว็บ [jsonlint.com](https://jsonlint.com) ก่อนอัปโหลดทุกครั้ง ไฟล์ JSON ผิด syntax แม้แค่จุดเดียวจะทำให้ **ทั้งแท็บนั้นโหลดไม่ขึ้นเลย**
3. **ตาราง (`table`/`tables`): จำนวนสมาชิกในแต่ละแถวของ `rows` ต้องเท่ากับจำนวน `columns`** เสมอ ไม่งั้นตารางจะเลื่อนคอลัมน์ผิด
4. **`source_url` ควรเป็นลิงก์ Google Drive แบบ "แชร์ให้ทุกคนที่มีลิงก์ดูได้"** ไม่งั้นผู้ใช้คนอื่นเปิดต้นฉบับไม่ได้
5. หลัง push ไฟล์ขึ้น GitHub แล้ว **GitHub Pages ใช้เวลา build 1-2 นาที** ถ้าเปิดแล้วยังเห็นข้อมูลเก่า ให้รอสักครู่ + ลอง hard refresh (Ctrl/Cmd+Shift+R) หรือล้าง cache เบราว์เซอร์ก่อนสรุปว่าอัปเดตไม่ติด

## 6. สรุปเร็ว — "อยากทำอะไร ไปแก้ไฟล์ไหน"

| อยากทำ | ไปที่ไฟล์ |
|---|---|
| เพิ่มระเบียบ/ข้อบังคับฉบับใหม่ | `data.json` |
| เพิ่มหัวข้อใหม่ในคู่มือบริหารชุมชน | `manual.json` |
| เพิ่มหัวข้อใหม่ในคู่มือจัดซื้อจัดจ้าง | `procurement.json` |
| เพิ่มบันทึกกรณีเฉพาะ/กฎหมายอ้างอิง/คู่มือเรื่องอื่นที่ยังไม่มีแท็บ | `criteria.json` |
| อยากได้คู่มือเล่มใหม่เป็นแท็บแยกของตัวเอง | ไฟล์ json ใหม่ + แก้ `index.html` (ดูข้อ 4) |
| แก้หน้าตา/สี/ฟอนต์/เลย์เอาต์ | `index.html` (ส่วน `<style>`) |
